Codeforces 5C Longest Regular Bracket Sequence - Solution

1. 题目数据 (Problem Metadata)

  • 题目类型：传统题
  • 题目链接：Problem - 5C - Codeforces
  • 时间限制：2 秒
  • 内存限制：256 MB

2. 题意简述 (Problem Summary)

给定长度为 nnn（1≤n≤1061 \le n \le 10^61≤n≤106）的字符串 sss，仅由 ( 与 ) 组成。设 LLL 为 sss 中最长合法括号子串的长度，CCC 为长度恰为 LLL 的合法括号子串个数。输出 LLL 与 CCC；若不存在任何合法括号子串，输出 0 1。

其中"合法括号序列"指可以通过在其中插入 + 与 1 得到正确数学表达式的序列，等价于经典定义：空串合法；若 AAA 合法则 (A)(A)(A) 合法；若 A,BA,BA,B 合法则 ABABAB 合法。

3. 朴素解法 (Brute-Force)

枚举所有子串区间 [l,r][l,r][l,r] 共 O(n2)O(n^2)O(n2) 个，对每个子串用栈判定是否合法（O(n)O(n)O(n)），总复杂度 O(n3)O(n^3)O(n3)；或预处理括号前缀和后用"区间左右括号数相等且任意前缀左括号数 ≥\ge≥ 右括号数"判定，降至 O(n2)O(n^2)O(n2)。当 n=106n = 10^6n=106 时均远超时限，必须利用子串的嵌套与拼接结构做线性 DP。

6. 复杂度分析 (Complexity)

  • 时间复杂度：O(n)O(n)O(n)。状态复杂度 O(n)O(n)O(n)，转移复杂度常数，每个位置 iii 只做常数次数组访问与比较，n=106n = 10^6n=106 时约几百万次运算，2 秒时限充裕。
  • 空间复杂度：O(n)O(n)O(n)，即 dp 数组与占位后的字符串，远低于 256 MB。

9. 补充说明 (Additional Notes)

  • 经典模型：本题是"最长合法括号子串"系列的最基础版本，与 LeetCode 32. Longest Valid Parentheses 同构，区别仅在输出要求多了"个数统计"。DP、栈、双向贪心三种主流解法在此题上等价可达 O(n)O(n)O(n)。
  • 计数语义的陷阱：题面"个数"指不同位置的子串个数（同一合法子串若可由不同 [l,r][l,r][l,r] 表示则分别计数），所以即便两段合法子串内容相同，只要位置不同就各计一次。dp + update_max 的方式按位置计数，可以做到不重不漏。

其他版本

本题我学习了三种解法，下面对比列出。

方法2（栈 + 最长连续段，O(n)O(n)O(n)）

思路最直观——用栈完成括号匹配，匹配成功的位置在 flag 中标记，最后统计 flag 连续段的长度与个数。是使用栈进行括号匹配的应用。

方法3（双向贪心 + set 去重）

从左到右、从右到左各扫一遍，用 left/right 计数在归零时记录合法段，并用 set<pair<int,int>> 去重。两次扫描分别覆盖"左括号多余"和"右括号多余"两种断点情况。

  • 理论复杂度：set::insert 单次 O(log⁡n)O(\log n)O(logn)，最坏情况下整体 O(nlog⁡n)O(n \log n)O(nlogn)。
  • 实际开销：set::insert 只在扫描中 left/right 归零且当前长度 ≥\ge≥ 已知最大值时才触发，而最长合法子串的数量通常远小于 nnn，使得实际插入次数很少。经实测在 n=106n = 10^6n=106 的数据下仅比 DP/栈写法慢约 30ms，2 秒时限下毫无压力。
  • 去重设计的合理性：两次扫描（从左、从右）会捕获同一合法段各一次，但表示区间的端点定义不同——左扫描用 [i-lth+1, i]，右扫描用 [i, i+lth-1]，因此同一区间两次插入的结果在 set 中天然一致，靠 set 去重是正确且简洁的做法，并非多余。

三种解法对比小结：DP 写法状态最紧凑、转移直接；栈写法思路最直观、适合初学者；双向贪心 + set 写法思路最巧妙——通过两次反向扫描覆盖两类断点，用 set 统一去重，避免了去重逻辑的显式编码。实际性能差距在 30ms 量级，三者都是可提交的优质解法，方法经典，都有学习的价值。
