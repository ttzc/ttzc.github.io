## Project Overview

Hexo 8.1.2 static blog using the Stellar theme, hosted on GitHub Pages. Author is a competitive programming contestant (算法竞赛) who also writes web notes (建站笔记). Posts are authored in Obsidian, published to Hexo via direct file placement.

## Commands

```bash
yarn run server   # hexo server — local dev
yarn run clean    # hexo clean — clear cache, required before build
yarn run build    # hexo generate — outputs to public/
yarn run deploy   # push public/ to gh-pages branch
```

Always run `yarn run clean` before `yarn run build`. Hexo caches post data in `db.json`; skipping clean causes stale cache to be reused and changes to be silently ignored. No linter or test framework exists. A clean build completing without errors is the only validation step.

## Branch Workflow

- **`main`** — source code only. Manually pushed after edits.
- **`gh-pages`** — generated static output from `public/`. Pushed automatically by `hexo deploy`; never edited manually.

Typical cycle: write/edit on `main` → `git push` → `hexo deploy` → GitHub Pages updates.

## Key Config Files

| File | Role |
|---|---|
| `_config.yml` | Hexo site settings: permalink, deploy target, markdown plugins, tag/category maps, RSS feed, abbrlink |
| `_config.stellar.yml` | Stellar theme overrides: katex, callout CSS injection, footer license, busuanzi counter |
| `package.json` | Dependencies managed by **yarn** (not npm). Scripts are thin wrappers around `hexo` CLI |

## Content Layout

Posts live under `source/_posts/` organized by Chinese-character directory names. The `themes/` directory only contains `.gitkeep` — the Stellar theme is installed in `node_modules/hexo-theme-stellar/`.

```
source/
  about/index.md          # layout: page, menu_id: about
  css/callout.css         # custom callout styles, injected via _config.stellar.yml
  _posts/
    .obsidian/            # Obsidian vault config (gitignored)
    算法竞赛/
      题解/{平台}/{文件名} - Solution.md
      代码模板/{主题}.md
      学习笔记/{主题}.md
    WEB/                  # site-building retrospective notes
```

Do **not** edit files inside `node_modules/hexo-theme-stellar/`. Theme customizations go in `_config.stellar.yml` or `source/css/`.

## Front Matter Convention

Posts require:
```yaml
---
title: 标题
category: 题解 | 学习笔记 | 代码模板 | 建站笔记
platform: LeetCode | Codeforces | AtCoder | Luogu   # solution posts only
tags: [tag1, tag2]
author: zaochen
abbrlink: <auto-generated or manually set>
date: YYYY-MM-DD
updated: YYYY-MM-DD   # set to today when editing an existing post; time portion is not displayed
---
```

Pages use `layout: page` + `menu_id` instead of category/platform.

When modifying any existing post, always update the `updated` field to today's date. `date` stays as the original publish date.

## abbrlink Behavior

Managed by `hexo-abbrlink` plugin. Key rules:

- **Config key is `alg`** (not `algorithm`). A typo silently falls back to `crc16` (4-char hex). Current config uses `alg: crc32` + `rep: hex` → 8-char CRC32 hex.
- **Auto-generated from title**: if no `abbrlink` in front matter, the plugin computes it on first build and writes it back into the source file. Value is deterministic from the title.
- **Manual override**: writing `abbrlink` manually in front matter is preserved across builds (default `force: false`). Use this for canonical/hand-picked short links.
- **Bulk regeneration**: temporarily set `force: true` in `_config.yml` to overwrite all abbrlinks, then set it back to `false`.

## Markdown & Rendering

Content is Chinese with LaTeX math (`$...$` / `$$...$$`), Obsidian-style callouts (`> [!note]`), and `[[双链]]` internal links. Rendering stack:

- `hexo-filter-titlebased-link` — resolves `[[双链]]` to site-internal links by matching filenames
- `markdown-it-obsidian-callouts`, `markdown-it-obsidian-images`, `markdown-it-obsidian-imgsize`, `markdown-it-task-lists` — extend markdown-it rendering
- KaTeX — enabled via Stellar config (`_config.stellar.yml`)

RSS feed is generated by `hexo-generator-feed` (Atom, `atom.xml`). Stellar's `head.ejs` already injects the `<link rel="alternate">` discovery tag, so `autodiscovery` is left as default.

## Deploy Message

The deploy timestamp template in `_config.yml` uses **lowercase** luxon format:
```yaml
message: "Site updated at {{ now('yyyy-MM-dd HH:mm:ss') }}"
```
Do not change to uppercase `YYYY` — that causes invalid timestamp generation.
