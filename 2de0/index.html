LeetCode 3501 操作后最大活跃区段数 II - Solution

1. 题目数据 (Problem Metadata)

  • 题目类型：传统题
  • 题目链接：3501. 操作后最大活跃区段数 II - 力扣（LeetCode）

2. 题意简述 (Problem Summary)

给定长度为 nnn（1≤n≤1051 \le n \le 10^51≤n≤105）的二进制字符串 sss，s[i]∈{’0’,’1’}s[i] \in \{\texttt{'0'}, \texttt{'1'}\}s[i]∈{’0’,’1’}，以及 qqq 个查询（1≤q≤1051 \le q \le 10^51≤q≤105），每个查询给出区间 [li,ri][l_i, r_i][li​,ri​]。对每个查询，将子串 s[li..ri]s[l_i..r_i]s[li​..ri​] 两端各补一个 ’1’\texttt{'1'}’1’ 得到 t=’1’+s[li..ri]+’1’t = \texttt{'1'} + s[l_i..r_i] + \texttt{'1'}t=’1’+s[li​..ri​]+’1’，在 ttt 上最多执行一次「交易」：

  1. 选一个被 ’0’\texttt{'0'}’0’ 包围的连续 ’1’\texttt{'1'}’1’ 块，整体变 ’0’\texttt{'0'}’0’；
  2. 再选一个被 ’1’\texttt{'1'}’1’ 包围的连续 ’0’\texttt{'0'}’0’ 块，整体变 ’1’\texttt{'1'}’1’。

求交易后 sss 全体中 ’1’\texttt{'1'}’1’ 的最大数量。各查询独立，两端补的 ’1’\texttt{'1'}’1’ 不计入答案。

由 I 版（3499） 的结论，一次交易的净效果是「选两个相邻的、被 1\texttt{1}1 包围的 0\texttt{0}0 块，连同中间的 1\texttt{1}1 块一起变成 1\texttt{1}1」，增量恰为两个 0\texttt{0}0 块长度之和。因此每个查询的答案为：

ansi=cnt1+max⁡valid pairs in [li,ri](zL.len+zR.len)\text{ans}_i = \text{cnt1} + \max_{\text{valid pairs in } [l_i, r_i]} \big(z_L.\text{len} + z_R.\text{len}\big) ansi​=cnt1+valid pairs in [li​,ri​]max​(zL​.len+zR​.len)

其中 cnt1\text{cnt1}cnt1 表示 sss 中 ’1’\texttt{'1'}’1’ 的总数。关键在于：两端的虚拟 ’1’\texttt{'1'}’1’ 使得查询边界处的 0\texttt{0}0 块（即使被截断）也能参与交易。

3. 朴素解法 (Brute-Force)

对每个查询，提取子串 s[li..ri]s[l_i..r_i]s[li​..ri​]，两端补 ’1’\texttt{'1'}’1’ 后分段，枚举所有相邻 0\texttt{0}0 块对取最大值。单次查询 O(ri−li+1)O(r_i - l_i + 1)O(ri​−li​+1)，总复杂度 O(nq)O(nq)O(nq)。n=q=105n = q = 10^5n=q=105 时约 101010^{10}1010 次运算，远超时限。

瓶颈在于每个查询都重复分段和枚举。所有查询共享同一个字符串，0\texttt{0}0 块分布是固定的，可以预处理分段信息后用区间最值数据结构加速查询。

4. 核心解法 (Main Solution)

特殊性质

交易增益只依赖两个相邻 0\texttt{0}0 块的长度之和。查询边界的虚拟 ’1’\texttt{'1'}’1’ 允许被截断的 0\texttt{0}0 块也能作为交易的 0\texttt{0}0 块——虚拟 ’1’\texttt{'1'}’1’ 充当其外侧边界。因此只需在预处理好的 0\texttt{0}0 块上做区间最值查询。

关键突破

从 sss 中提取所有 0\texttt{0}0 块 z1,z2,…,zkz_1, z_2, \dots, z_kz1​,z2​,…,zk​（按出现顺序），对相邻对预计算 wi=zi.len+zi+1.lenw_i = z_i.\text{len} + z_{i+1}.\text{len}wi​=zi​.len+zi+1​.len（i=1,…,k−1i = 1, \dots, k-1i=1,…,k−1），用稀疏表（Sparse Table）维护 wiw_iwi​ 的区间最大值。对每个查询，二分定位查询边界处的 0\texttt{0}0 块，分四种情况计算最大增益。

5. 正确性证明 (Proof of Correctness)

需证四种情况不重不漏地覆盖了所有可能的交易。

在 t=’1’+s[l..r]+’1’t = \texttt{'1'} + s[l..r] + \texttt{'1'}t=’1’+s[l..r]+’1’ 中，一次交易选两个被 1\texttt{1}1 包围的相邻 0\texttt{0}0 块。这两个 0\texttt{0}0 块在查询范围内的位置关系有以下几种：

两个 0\texttt{0}0 块都完全在 [l,r][l, r][l,r] 内。 它们对应 zfst,…,zlstz_{\text{fst}}, \dots, z_{\text{lst}}zfst​,…,zlst​ 中的某对相邻 0\texttt{0}0 块，增益由 Sparse Table 覆盖（情况 ④）。

左 0\texttt{0}0 块被截断（起始 <l\lt l<l），右 0\texttt{0}0 块完全在区间内。 左 0\texttt{0}0 块在区间内的部分为 left0\text{left}_0left0​，虚拟 ’1’\texttt{'1'}’1’ 在其左侧充当中间 1\texttt{1}1 块的备选边界。左截断 0\texttt{0}0 块必定结束于 zfst.l−1z_{\text{fst}}.l - 1zfst​.l−1 之前（否则与 zfstz_{\text{fst}}zfst​ 合并为同一块），且 zfst.l−1z_{\text{fst}}.l - 1zfst​.l−1 位置是 ’1’\texttt{'1'}’1’。因此 left0\text{left}_0left0​ 个 0\texttt{0}0 与 zfstz_{\text{fst}}zfst​ 中的 0\texttt{0}0 被至少一个 ’1’\texttt{'1'}’1’ 隔开，满足交易条件。增益为 left0+zfst.len\text{left}_0 + z_{\text{fst}}.\text{len}left0​+zfst​.len（情况 ①）。

右 0\texttt{0}0 块被截断，左 0\texttt{0}0 块完全在区间内。 与上对称（情况 ②）。

两个 0\texttt{0}0 块都被截断。 此时查询区间内没有完整的 0\texttt{0}0 块（即 fst>lst\text{fst} > \text{lst}fst>lst），所有 0\texttt{0}0 来自左右截断部分。区间内容恰好由 left0\text{left}_0left0​ 个 0\texttt{0}0、一段 1\texttt{1}1、right0\text{right}_0right0​ 个 0\texttt{0}0 组成——条件 left0+right0+(区间内 1 数)=r−l+1\text{left}_0 + \text{right}_0 + (区间内\ \texttt{1}\ 数) = r - l + 1left0​+right0​+(区间内 1 数)=r−l+1 恰好刻画了这一情况。若等式不成立，说明区间内存在完整 0\texttt{0}0 块，应归入前面三种情况之一。增益为 left0+right0\text{left}_0 + \text{right}_0left0​+right0​（情况 ③）。

四种情况互斥（由 0\texttt{0}0 块在区间内的位置关系决定）且完备（覆盖两个 0\texttt{0}0 块的所有位置关系），不重不漏。最终答案在所有适用情况中取最大值加上 cnt1\text{cnt1}cnt1。综上所述，算法正确。

  • 时间复杂度：预处理 O(n+klog⁡k)O(n + k\log k)O(n+klogk)（分段 O(n)O(n)O(n)，ST 表 O(klog⁡k)O(k\log k)O(klogk)，kkk 为 0\texttt{0}0 块数，k≤nk \le nk≤n）。每次查询 O(log⁡k)O(\log k)O(logk)（二分）+ O(1)O(1)O(1)（ST 查询）。总复杂度 O(nlog⁡n+qlog⁡n)O(n \log n + q \log n)O(nlogn+qlogn)，n=q=105n = q = 10^5n=q=105 时约 2×1062 \times 10^62×106 次运算，轻松通过。
  • 空间复杂度：O(nlog⁡n)O(n \log n)O(nlogn)（ST 表 O(klog⁡k)O(k\log k)O(klogk) + 前缀和与分段数组 O(k)O(k)O(k)），未超典型内存限制。
  • 常数优化：ST 表查询 O(1)O(1)O(1) 已是最优；lg⁡\lglg 数组只初始化到 k−1k-1k−1 而非 NNN，在多次测试用例场景中可减少不必要计算。线段树替代 ST 表会多一个 log⁡\loglog 因子，常数也更大，不必引入。

7. 实现细节与避坑指南 (Implementation Details)

坑点 说明
1-based 索引 代码在 sss 前补空格（s = " " + s），数组下标从 111 开始。查询传入的 0-based 下标需 +1+1+1 转换（ql = q[0] + 1, qr = q[1] + 1）。前缀和数组 f0[0]、f1[0] 为全局变量自动初始化为 000。
二分边界处理 当 zr=1z_r = 1zr​=1 且唯一 0\texttt{0}0 块不完全在 [l,r][l, r][l,r] 内时，二分不执行（cl=crcl = crcl=cr），fst_chk / lst_chk 可能指向不在区间内的 0\texttt{0}0 块。后续的 valid_fst / valid_lst 检查（判断该块是否完全被 [l,r][l, r][l,r] 包含）会过滤此情况，确保不会错误触发增益计算。
zr=0z_r = 0zr​=0 的无 0\texttt{0}0 情况 当 sss 全为 ’1’\texttt{'1'}’1’ 时 zr=0z_r = 0zr​=0（无 0\texttt{0}0 块），代码未显式提前返回。此时二分搜索 cr=0cr = 0cr=0，cl=crcl = crcl=cr 不执行循环，fst_chk = 1, lst_chk = 0。zeros[1] 为全局零初始化（l = r = 0），后续 valid_fst、valid_lst 均为 false，所有增益条件均不满足，答案退化为 f1[n] = n。虽然结果正确但 f0[-1] 一次越界访问属于 UB，建议在开头加 if (zr == 0) return vector<int>(queries.size(), n); 提前返回。首次写代码时忽略了这个问题，但是仍然通过了所有测试数据。
ST 表建表循环边界 相邻对数组 www 有 k−1k-1k−1 个元素（下标 1..k−11..k-11..k−1）。建表时 i < zr 恰好覆盖 i=1..k−1i = 1..k-1i=1..k−1；pow2(j) < zr 确保 2j≤k−12^j \le k-12j≤k−1。查询条件 fst_chk < lst_chk 保证 l≤rl \le rl≤r（ST_query(fst_chk, lst_chk - 1) 中 l≤rl \le rl≤r）。
lg⁡\lglg 数组初始化范围 lg[1] = 0; for i=2..zr-1 只初始化到 k−1k-1k−1。ST 查询的最大区间长度为 k−1k-1k−1，lg[k−1]lg[k-1]lg[k−1] 已包含。标准写法可初始化到 NNN，但当前范围已足够且避免多余计算。
前缀和数组的 f0 与 f1 f0[i] = s[1..i]s[1..i]s[1..i] 中 ’0’\texttt{'0'}’0’ 的个数，f1[i] = ’1’\texttt{'1'}’1’ 的个数。区间内 1\texttt{1}1 数 = f1[r] - f1[l-1]，区间内 0\texttt{0}0 数 = f0[r] - f0[l-1]。f0 同时用于计算截断部分的 0\texttt{0}0 数。
多测试用例 LeetCode 上全局数组不会自动清零，但本代码会覆盖所有使用到的下标（f0[0..n]、chks[1..chk]、zeros[1..zr]、st[1..zr-1][*]、lg[1..zr-1]），无需手动清空。事实上，在写本题前，我不太了解 Leetcode 的多测机制，调试时发现把 chk 和 zr 两个全局变量放到函数中就可以实现清零的效果。

9. 补充说明 (Additional Notes)

  • 题目背景：本题是 LeetCode 3501（难度分 2941，Hard），与 I 版 3499 同属「操作后最大活跃区段数」系列。I 版是单次查询 O(n)O(n)O(n) 线性扫描；II 版引入 q≤105q \le 10^5q≤105 个查询，需要 ST 表（或线段树）将单次查询降至 O(log⁡n)O(\log n)O(logn)。两者的核心思想一脉相承：交易的净效果是合并两个相邻 0\texttt{0}0 块。
  • ST 表 vs 线段树：本题无修改操作，ST 表 O(1)O(1)O(1) 查询优于线段树 O(log⁡n)O(\log n)O(logn)，且常数更小、实现更短。当 q=105q = 10^5q=105 时，ST 表的优势更加明显。线段树实现可作为替代方案，思路相同：维护区间内相邻 0\texttt{0}0 块长度之和的最大值，处理 RMQ。
  • 官方 Hint：此题官方给出了 5 条 Hint 作为解题引导——分段编号、答案公式为相邻段长度和、0\texttt{0}0 段定义 ans[i]=0ans[i] = 0ans[i]=0、三段均需完全在区间内、用线段树做区间最值并单独处理首尾。我上面的实现正是这条路径的完整版本，只是我觉得用 ST 表处理本题更合适。
  • 码风说明：1-based 索引（字符串前补空格）、全局数组、pow2 宏是 OI 赛制下的常见习惯，避免频繁传参和重复计算。在 LeetCode 上使用全局数组时只需注意：每次调用会覆盖使用到的下标区域，无需额外清空。
